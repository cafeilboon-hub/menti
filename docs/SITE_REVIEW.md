# 현재 사이트 검토

검토일: 2026-08-17  
대상: <https://cafeilboon-hub.github.io/menti/>

## 현재 상태

- 13개 이야기 단위를 7장 전체 화면 웹 리포트로 재구성했습니다.
- `첫 화면 → 문제 → 멘토의 연결 → 실행 → 결과 → Before/After → What we learned → 첫 화면`으로 순환합니다.
- 각 장은 헤더를 제외한 화면 높이를 차지하고 스크롤 스냅으로 정렬됩니다.
- 데스크톱과 390 × 844 모바일 화면을 반응형으로 지원합니다.
- 상단 장 탐색, `다음 내용`, 각 장 URL 해시 직접 이동을 제공합니다.
- 프레임워크 없이 `index.html` 한 파일로 동작하며 Material Symbols 아이콘 폰트만 외부에서 불러옵니다.

## 2번 경로형 서사 개편

- 발표 흐름을 `문제 → 멘토의 연결 → 실행 → 결과`의 화면형 공개 리포트로 재구성했습니다.
- 첫 화면에서 접점 3개와 결과 6개의 관계를 한눈에 볼 수 있게 했습니다.
- 성과 상태, 기준일, 멘토링 결과와 자체 제품 작업의 구분을 명시했습니다.
- 모바일 비교표를 가로 스크롤 없이 세로로 읽도록 바꿨습니다.
- 상단 탐색과 `다음 내용`, 두 곳의 `motioncore.ai` CTA를 추가했습니다.
- 표와 목록을 구리·오커·세이지·슬레이트 색상으로 구분했습니다.
- 장별 페이드·슬라이드·줌인·줌아웃 전환과 모션 감소 설정을 적용했습니다.
- 데스크톱·모바일 비교와 상호작용 검증 결과는 `design-qa.md`에 남겼습니다. 캡처 파일은 로컬 QA 자료로만 보관합니다.

아직 남은 보강은 공개 허가를 받은 실제 증빙 자료와 데모·미팅 요청 경로입니다. 확인되지 않은 자료는 목업이나 생성 이미지로 대신하지 않습니다.

## 유지해야 할 강점

- “접점 3 → 결과 6”의 구조가 그래픽과 이야기에서 일관됩니다.
- 첫 장과 마지막 장이 같은 숫자로 닫혀 기억점이 분명합니다.
- 확인되지 않은 실명과 협업사 이름을 공개하지 않습니다.
- 수치가 적고 구체적이며, 멘토링 성과와 자체 성과를 분리합니다.
- 자바스크립트가 없어도 기본 콘텐츠가 HTML에 남아 있습니다.

## 콘텐츠 검토가 필요한 지점

1. 기존 기획서는 12장을 전제로 하지만 현재 사이트는 13개 이야기 단위를 7장 화면에 배치합니다. 앞으로는 `docs/CONTENT.md`를 공개 원고 기준으로 관리해야 합니다.
2. 현재 결과는 발표 흐름과 장기 보관형 웹 리포트의 성격을 함께 가집니다. 발표 후 읽는 외부 독자를 위한 근거와 다음 행동은 계속 보강할 수 있습니다.
3. 제품 성공 기준은 데모나 미팅 요청인데, 현재 외부 행동은 `motioncore.ai` 링크 하나뿐입니다. 연락 또는 데모 요청 경로는 다음 개편에서 결정해야 합니다.
4. 기획서가 제안한 반디포럼 현장 사진, 제품 화면, 선정 안내 같은 증빙 자산이 현재 공개판에는 없습니다. 공개 권한을 확인한 뒤 근거 섹션을 보강할 수 있습니다.
5. “1,500개 매장”, “연말 2,000 매장”, “아시아 6개국”, “3개사 협업” 등 시점에 따라 변하는 수치는 기준일과 근거를 재확인해야 합니다.
6. 공개일 직전 문구인 “2026. 08. 19”가 들어 있으므로 실제 발표 후 상태와 후속 성과를 반영하는 개정 이력이 필요합니다.

## 기술 구조의 한계

- 원고, 스타일, 인터랙션이 약 56KB의 `index.html`에 함께 있어 문구 하나를 바꿔도 전체 파일을 검토해야 합니다.
- Markdown 원고와 HTML 사이에 자동 동기화가 아직 없습니다.
- 변경 전후 화면을 비교하는 회귀 테스트와 접근성 자동 검사가 없습니다.
- 소셜 공유용 `og:image`가 없어 메신저·SNS 카드에서 시각적 맥락이 약합니다.
- 상세 QA 캡처는 저장소 용량과 배포 파일을 줄이기 위해 로컬에서만 관리합니다.

## 다음 개편 후보

콘텐츠 검토가 끝난 뒤 다음 순서가 안전합니다.

1. `docs/CONTENT.md`를 승인된 공개 원고로 확정합니다.
2. 원고를 구조화된 데이터로 분리하고 정적 HTML 생성 절차를 만듭니다.
3. 증빙 자료의 공개 권한과 최신 수치를 확인합니다.
4. 근거 자료와 외부 CTA를 추가한 확장형 화면을 설계합니다.
5. 데스크톱·모바일·키보드·모션 감소 상태를 자동 검사합니다.
6. 로컬 검토를 통과한 변경만 GitHub Pages에 반영합니다.
